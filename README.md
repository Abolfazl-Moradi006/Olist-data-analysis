# Olist Data Analysis

Exploratory data analysis of the [Olist Brazilian e-commerce dataset](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce): about 100k orders placed between 2016 and 2018, with customers, sellers, products, payments, reviews, and geolocation.

## Setup

Requires **Python 3.12 or newer**.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

## How to run

Run the notebooks in order, from the `Notebooks/` folder (paths are relative to it):

| # | Notebook | What it does |
|---|---|---|
| 1 | `1_understanding_data.ipynb` | Structure of the 9 raw tables: grain, keys, types, duplicates, missing values |
| 2 | `2_data_cleaning.ipynb` | Cleans and validates the 8 tables, checks joins, and writes `Data/Processed/*.parquet` |
| 3 | `3_order_status_time_trends.ipynb` | Order status analysis and monthly / yearly order trends (DuckDB over the Parquet files) |

**Notebook 2 must be run before notebook 3**, because the processed files are generated, not stored in git.

## Folder layout

```
Data/
  Raw/          original Kaggle CSVs (tracked in git)
  Processed/    cleaned Parquet files, generated by notebook 2 (ignored by git)
Notebooks/      analysis notebooks, run in numeric order
Reports/        written reports (data_cleaning_report.md)
```

## Processed data

Cleaned tables are stored as **Parquet**, which keeps column types: ZIP prefixes stay zero-padded strings, timestamps stay datetimes, and flag columns stay boolean. Load them without any type arguments:

```python
orders = pd.read_parquet("../Data/Processed/orders_clean.parquet")
```

or in DuckDB:

```python
con.execute("CREATE OR REPLACE VIEW orders AS SELECT * FROM read_parquet('../Data/Processed/orders_clean.parquet')")
```

| File | Grain |
|---|---|
| `orders_clean` | one row per order (with delivery metrics and anomaly flags) |
| `customers_clean` | one row per `customer_id` |
| `order_items_clean` | one row per (`order_id`, `order_item_id`) |
| `products_clean` | one row per product (English categories) |
| `sellers_clean` | one row per seller |
| `payments_clean` | one row per (`order_id`, `payment_sequential`) |
| `reviews_clean` | one row per (`review_id`, `order_id`) |
| `geolocation_clean` | cleaned coordinate points (many per ZIP prefix) |
| `geolocation_prefix` | one row per ZIP prefix (median coordinates). **Use this one for joins** |

The rules for joining these tables (what to aggregate first, which revenue source to use) are in section 7 of [`Reports/data_cleaning_report.md`](Reports/data_cleaning_report.md).
